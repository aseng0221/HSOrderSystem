# Task: Auto-incrementing, Daily Resetting Order Numbers

## Request
Implement a daily resetting order number system. Orders created from the POS should start at 1000, and orders from the mobile app should start at 3000. It resets every day. This replaces the 6-character sliced order ID for better readability.

## Plan
1. Add `orderNumber` and `orderSource` to the `Order` type definition.
2. Update the main App's checkout flow (`CartScreen.tsx`) to explicitly tag orders with `orderSource: 'app'`.
3. Create a Firestore Cloud Function trigger (`onOrderCreated`) to generate daily-resetting numbers atomically using a transaction. It uses Malaysia time (UTC+8).
4. Refactor the main app's UI screens to display `orderNumber`, falling back to the legacy ID slice if missing.
5. Explain to the user how to update the POS app (which was inaccessible).

## Actions Taken
- Updated `src/types/order.ts`.
- Patched `src/screens/CartScreen.tsx` (all 3 checkout variants).
- Appended `onOrderCreated` function in `functions/src/index.ts`.
- Patched UI components in `src/screens/OrderHistoryScreen.tsx` and `src/screens/OrderHistoryDetailScreen.tsx`.
- Ran `tsc` in root and `npm run build` in `functions` to verify type safety and compilation.
- Sent instructions to the user regarding the POS repository changes.
